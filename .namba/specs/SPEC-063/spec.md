# SPEC-063 Sync-managed verification guide and final-report detail preservation

## Problem

NambaAI already exposes local quality guidance in `README.md` and command-flow guidance in `docs/workflow-guide.md`, but the verification story is spread across generated docs, `scripts/quality.sh`, eval/report commands, CI, and `.namba` evidence paths. Operators need a single verification guide that is regenerated by `namba sync` alongside the workflow guide, so it does not drift or disappear after generated docs refresh.

There is also a final-response hook issue: the hook asks Codex to rewrite the answer into the Namba report frame, but that can collapse or erase detailed content that appeared before the hook feedback. The final frame must preserve substantive details, not replace them with a thin summary.

## Goal

Add a `docs/verification-guide.md` documentation surface that is produced by the `namba sync` generation path and linked from README and workflow guide surfaces. Update the final-report hook or output contract so the required Namba report frame retains the important details from the pre-hook response.

## Scope

- Generate the verification guide through the same durable source path used for README and workflow docs, such as the README/docs renderer and `.namba/config/sections/docs.yaml`.
- Link the guide from README read-next/navigation surfaces and workflow-guide navigation/reference surfaces through generated output, not one-off hand edits.
- Cover `namba eval`, `namba report`, `scripts/quality.sh`, accumulated `.namba` evidence, CI consumption, and failure interpretation.
- Preserve current CLI semantics for eval, report, quality, CI, and evidence generation unless a discovered behavior makes accurate documentation impossible.
- Update hook prompt/template/output-contract validation so the final `# NAMBA-AI 작업 결과 보고` frame folds in existing detailed findings, validation, file paths, blockers, and next commands.
- Add targeted tests or golden assertions for generated docs/navigation and final-report detail preservation.

## Non-goals

- No new public verification command.
- No change to the meaning of `namba eval`, `namba report`, `scripts/quality.sh`, CI workflows, or `.namba` evidence schemas unless implementation finds a hard documentation mismatch.
- No manual-only edits to generated README or generated workflow-guide files as the durable fix.
- No visual frontend, image generation, browser UI, or design-system work.

## Generated-doc contract

- `namba sync` must be able to regenerate the verification guide and all links from source files or renderer logic.
- Generated output may include localized verification-guide siblings if that matches the existing docs renderer pattern. If the implementation intentionally ships English-only in this SPEC, localized navigation must either avoid missing links or link clearly to the canonical English guide.
- A post-sync diff check must prove generated docs are idempotent from the committed or staged state.

## Hook/output contract

- The final hook feedback may enforce the Namba report frame and section order.
- It must not require discarding already prepared details.
- The rewrite instruction should explicitly say to preserve concrete file paths, commands, validation results, blockers, evidence paths, and actionable next steps inside the required sections.
- Validation should include a representative detailed pre-hook answer and prove the rewritten output still contains the substantive details.

## Acceptance summary

- `namba sync` regenerates `docs/verification-guide.md` and README/workflow-guide links without drift.
- The guide explains local verification commands, quality artifacts, accumulated `.namba` evidence, CI consumption, and failure interpretation.
- Tests or golden assertions cover the sync-managed guide and navigation.
- Hook/output-contract tests prove final Namba report framing preserves detailed content while keeping the required Korean sections: `🧭 작업 정의`, `🧠 판단`, `🛠 수행한 작업`, `🚧 현재 이슈`, `⚠ 잠재 문제`, `➡ 다음에 해야 할 작업`.
- `scripts/quality.sh` passes, or any environmental blocker is recorded with the exact command, failure, and artifact path.
