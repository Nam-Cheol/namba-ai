# Behavior Preservation Checklist

This checklist must be completed in Phase 0 before refactoring and re-run in Phase 7 after refactoring.

## 1. Command Routing

- [ ] Public command names remain: `init`, `doctor`, `status`, `project`, `plan`, `harness`, `fix`, `run`, `queue`, `sync`, `pr`, `land`, `release`, `regen`, `update`, `eval`, `report`, `worktree`.
- [ ] Documented help forms remain meaningful: no args, `--help`, `-h`, `help <command>`, and command-specific help where supported.
- [ ] Internal-only command surfaces do not leak into public usage.
- [ ] Unknown command error behavior remains unchanged.
- [ ] Command ordering in public usage remains stable unless tests prove ordering is not part of the contract.

## 2. Argument Parsing

- [ ] Missing required argument errors are preserved.
- [ ] Invalid flag errors are preserved.
- [ ] SPEC ID parsing accepts the same forms and rejects the same invalid forms.
- [ ] Description commands keep the same behavior for quoted descriptions, empty descriptions, and too many args.
- [ ] Queue range/list arguments keep the same expansion and ordering.
- [ ] Default options for language, branch, review, validation, remotes, run mode, and output format are preserved.

## 3. Exit Code And Error Contract

- [ ] Successful commands still exit successfully.
- [ ] Usage errors still fail.
- [ ] Clarification-required planning errors still fail without creating a SPEC.
- [ ] Invalid project root errors remain actionable.
- [ ] Missing config/file errors remain visible.
- [ ] Blocked/unsafe scenarios still fail closed.

## 4. Output Contract

- [ ] stdout key phrases for human summaries are preserved.
- [ ] stderr key phrases for errors are preserved.
- [ ] JSON outputs keep schema version, required fields, and parseability.
- [ ] Markdown/text report outputs keep their semantic sections.
- [ ] Automation-parsed phrases remain present.
- [ ] Help output meaning is preserved without overfitting incidental whitespace.

## 5. File Side Effects

- [ ] `.namba/specs` layout is unchanged.
- [ ] `.namba/logs` layout is unchanged.
- [ ] `.namba/project` layout is unchanged.
- [ ] `.namba/releases` layout is unchanged.
- [ ] `.codex/hooks` generated layout is unchanged.
- [ ] Evidence files keep the same names, schema versions, and required fields.
- [ ] Report/eval artifacts keep their expected names and schema.
- [ ] README/docs managed outputs remain generated by the same command paths.

## 6. SPEC Creation Behavior

- [ ] `namba plan` creates the same SPEC scaffold files.
- [ ] `namba harness` creates the same harness-oriented scaffold files and sidecars.
- [ ] `namba fix --command plan` creates the same bugfix SPEC scaffold.
- [ ] SPEC ID allocation remains sequential and repository-aware.
- [ ] Ambiguous request clarification gate remains before mutation.
- [ ] `--current-workspace` behavior remains unchanged.
- [ ] Auto review guidance remains present for `namba plan` unless `--no-review` is used.

## 7. Run And Evidence Behavior

- [ ] `namba run SPEC-XXX` loads the same SPEC package files.
- [ ] Hook evidence is generated in the same location and schema.
- [ ] Validation evidence is generated in the same location and schema.
- [ ] Failure evidence is generated when validation or execution fails.
- [ ] Dry-run or simulation behavior, where present, is unchanged.
- [ ] Blocked command evidence remains visible.

## 8. Queue Behavior

- [ ] `queue start`, `status`, `resume`, `pause`, and `stop` semantics are unchanged.
- [ ] Queue item ordering is unchanged.
- [ ] Pending, running, blocked, and done states are unchanged.
- [ ] Blocked reason recording is unchanged.
- [ ] Resume preconditions are unchanged.
- [ ] Queue evidence is generated in the same location and schema.

## 9. Eval And Report Behavior

- [ ] `namba eval --suite harness` baseline regression behavior is unchanged.
- [ ] Scorecard JSON schema and key fields are unchanged.
- [ ] Summary markdown semantics are unchanged.
- [ ] `namba report --format json` schema validation still passes.
- [ ] Missing data graceful degradation is unchanged.

## 10. Security And Guardrail Behavior

- [ ] Dangerous command blocking remains fail-closed.
- [ ] Hook guard behavior is unchanged.
- [ ] Approval/request risk messaging remains visible.
- [ ] Secret/vulnerability quality gates are not bypassed.
- [ ] Unsafe scenarios are not hidden or converted into success.

## 11. Release, PR, And Land Behavior

- [ ] `namba pr` sync/validate/commit/push/PR semantics are unchanged.
- [ ] `namba land` clean PR and local main update semantics are unchanged.
- [ ] `namba release` clean working tree, version, notes, tag, and optional push semantics are unchanged.
- [ ] Clean working tree requirements remain enforced.
- [ ] Release checklist and release evidence behavior are unchanged.
- [ ] GitHub/external dependency behavior remains covered by fake/simulation tests.

## 12. Idempotency

- [ ] Re-running `namba init` in an initialized repo behaves the same.
- [ ] Re-running `namba project` behaves the same.
- [ ] Re-running `namba sync` behaves the same.
- [ ] Re-running `namba report` behaves the same.
- [ ] Already-initialized repo handling is unchanged.

## 13. Cross-Platform Assumptions

- [ ] Windows path separator handling is preserved.
- [ ] POSIX shell launcher behavior is preserved.
- [ ] PowerShell launcher behavior is preserved.
- [ ] Path normalization remains stable.
- [ ] Temp directory handling remains stable.
