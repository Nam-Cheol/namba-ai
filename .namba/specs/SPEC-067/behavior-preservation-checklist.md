# Behavior Preservation Checklist

This checklist must be completed in Phase 0 before refactoring and re-run in Phase 7 after refactoring.

## 1. Command Routing

- [x] Public command names remain: `init`, `doctor`, `status`, `project`, `plan`, `harness`, `fix`, `run`, `queue`, `sync`, `pr`, `land`, `release`, `regen`, `update`, `eval`, `report`, `worktree`.
- [x] Documented help forms remain meaningful: no args, `--help`, `-h`, `help <command>`, and command-specific help where supported.
- [x] Internal-only command surfaces do not leak into public usage.
- [x] Unknown command error behavior remains unchanged.
- [x] Command ordering in public usage remains stable unless tests prove ordering is not part of the contract.

## 2. Argument Parsing

- [x] Missing required argument errors are preserved.
- [x] Invalid flag errors are preserved.
- [x] SPEC ID parsing accepts the same forms and rejects the same invalid forms.
- [x] Description commands keep the same behavior for quoted descriptions, empty descriptions, and too many args.
- [x] Queue range/list arguments keep the same expansion and ordering.
- [x] Default options for language, branch, review, validation, remotes, run mode, and output format are preserved.

## 3. Exit Code And Error Contract

- [x] Successful commands still exit successfully.
- [x] Usage errors still fail.
- [x] Clarification-required planning errors still fail without creating a SPEC.
- [x] Invalid project root errors remain actionable.
- [x] Missing config/file errors remain visible.
- [x] Blocked/unsafe scenarios still fail closed.

## 4. Output Contract

- [x] stdout key phrases for human summaries are preserved.
- [x] stderr key phrases for errors are preserved.
- [x] JSON outputs keep schema version, required fields, and parseability.
- [x] Markdown/text report outputs keep their semantic sections.
- [x] Automation-parsed phrases remain present.
- [x] Help output meaning is preserved without overfitting incidental whitespace.

## 5. File Side Effects

- [x] `.namba/specs` layout is unchanged.
- [x] `.namba/logs` layout is unchanged.
- [x] `.namba/project` layout is unchanged.
- [x] `.namba/releases` layout is unchanged.
- [x] `.codex/hooks` generated layout is unchanged.
- [x] Evidence files keep the same names, schema versions, and required fields.
- [x] Report/eval artifacts keep their expected names and schema.
- [x] README/docs managed outputs remain generated by the same command paths.

## 6. SPEC Creation Behavior

- [x] `namba plan` creates the same SPEC scaffold files.
- [x] `namba harness` creates the same harness-oriented scaffold files and sidecars.
- [x] `namba fix --command plan` creates the same bugfix SPEC scaffold.
- [x] SPEC ID allocation remains sequential and repository-aware.
- [x] Ambiguous request clarification gate remains before mutation.
- [x] `--current-workspace` behavior remains unchanged.
- [x] Auto review guidance remains present for `namba plan` unless `--no-review` is used.

## 7. Run And Evidence Behavior

- [x] `namba run SPEC-XXX` loads the same SPEC package files.
- [x] Hook evidence is generated in the same location and schema.
- [x] Validation evidence is generated in the same location and schema.
- [x] Failure evidence is generated when validation or execution fails.
- [x] Dry-run or simulation behavior, where present, is unchanged.
- [x] Blocked command evidence remains visible.

## 8. Queue Behavior

- [x] `queue start`, `status`, `resume`, `pause`, and `stop` semantics are unchanged.
- [x] Queue item ordering is unchanged.
- [x] Pending, running, blocked, and done states are unchanged.
- [x] Blocked reason recording is unchanged.
- [x] Resume preconditions are unchanged.
- [x] Queue evidence is generated in the same location and schema.

## 9. Eval And Report Behavior

- [x] `namba eval --suite harness` baseline regression behavior is unchanged.
- [x] Scorecard JSON schema and key fields are unchanged.
- [x] Summary markdown semantics are unchanged.
- [x] `namba report --format json` schema validation still passes.
- [x] Missing data graceful degradation is unchanged.

## 10. Security And Guardrail Behavior

- [x] Dangerous command blocking remains fail-closed.
- [x] Hook guard behavior is unchanged.
- [x] Approval/request risk messaging remains visible.
- [x] Secret/vulnerability quality gates are not bypassed.
- [x] Unsafe scenarios are not hidden or converted into success.

## 11. Release, PR, And Land Behavior

- [x] `namba pr` sync/validate/commit/push/PR semantics are unchanged.
- [x] `namba land` clean PR and local main update semantics are unchanged.
- [x] `namba release` clean working tree, version, notes, tag, and optional push semantics are unchanged.
- [x] Clean working tree requirements remain enforced.
- [x] Release checklist and release evidence behavior are unchanged.
- [x] GitHub/external dependency behavior remains covered by fake/simulation tests.

## 12. Idempotency

- [x] Re-running `namba init` in an initialized repo behaves the same.
- [x] Re-running `namba project` behaves the same.
- [x] Re-running `namba sync` behaves the same.
- [x] Re-running `namba report` behaves the same.
- [x] Already-initialized repo handling is unchanged.

## 13. Cross-Platform Assumptions

- [x] Windows path separator handling is preserved.
- [x] POSIX shell launcher behavior is preserved.
- [x] PowerShell launcher behavior is preserved.
- [x] Path normalization remains stable.
- [x] Temp directory handling remains stable.
