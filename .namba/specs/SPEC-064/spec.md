# SPEC-064

## Problem

`namba init` currently prints Korean onboarding copy before the user can choose a human language, then asks for repository state and project defaults before the language step. This makes the first-run path hard to understand for English, Japanese, and Chinese users, and it exposes localized terminals to fragile emoji rendering through country flag labels.

The requested change is a CLI terminal onboarding redesign, not a change to init semantics. The wizard should feel more polished and explanatory, but it must still derive defaults from repository state first, keep existing flags compatible, and preserve non-interactive behavior.

## Goal

Redesign the `namba init` onboarding wizard so first-run setup is understandable before language selection and feels polished across localized terminals without changing what init writes or how flags behave.

## Current Evidence

- `internal/namba/namba.go` runs the wizard only when `--yes` is not set and stdin/stdout are interactive terminals. Non-TTY init flows currently resolve defaults and skip the wizard.
- `internal/namba/namba.go` detects human language defaults from `NAMBA_LANG`, `LC_ALL`, then `LANG`, and supports `ko`, `en`, `ja`, and `zh`.
- `internal/namba/namba.go` currently starts the wizard with Korean banner/hints before `wizardStepHumanLanguage`.
- `internal/namba/namba.go` currently renders language choices with country flag emoji in `languageOptions`.
- `internal/namba/codex_access.go` owns Codex access preset semantics and previews the resulting `approval_policy` and `sandbox_mode`.
- `internal/namba/readme.go` generates localized getting-started docs for `ko`, `en`, `ja`, and `zh`.
- `internal/namba/init_wizard_test.go` already covers detected-stack behavior, `b`/`back`, locale syncing, prompt output, and visible step numbering.

## Scope

- Add a language-first entry screen that appears before repository-state prompts.
- Make the default language selection locale-aware and visibly overridable.
- Replace country flag language labels with emoji-safe labels that render predictably across terminals.
- Add a lightweight stage progress rail for the wizard without requiring a full-screen TUI.
- Add a repo-intelligence header after language selection that summarizes target path, detected repository state, detected stack, methodology, and default setup assumptions.
- Reframe setup choices as purpose-first paths, with recommended badges based on existing repo state and current defaults.
- Keep the Codex access preset preview but improve the surrounding copy so users understand the consequence before selecting.
- Add Git setup guidance that explains manual, personal, and team modes without asking for a GitHub username.
- Replace the final summary with a ready handoff card that confirms generated behavior and next steps.
- Add a non-TTY and ASCII/plain-terminal fallback so output remains usable when emoji, ANSI styling, raw-key selection, or terminal capabilities are unavailable.
- Update init help text, generated docs, and tests for `ko`, `en`, `ja`, and `zh` (Simplified Chinese) parity.

## Non-Goals

- Do not change the files generated by `namba init` except for text that is already generated from the same profile values.
- Do not add mandatory full-screen TUI behavior.
- Do not change existing init flags, flag meanings, or default config values.
- Do not change Codex access preset IDs, policy pairs, or `namba codex access` semantics.
- Do not reintroduce GitHub username collection.
- Do not convert this into a web frontend, image-generation, or browser UI task.

## Required Behavior

- Interactive init starts with a language selector whose default comes from the existing locale detection path.
- Before language selection, the screen is understandable without Korean knowledge: it shows a compact language-neutral or multilingual prompt, the supported language codes, the current default, and how to continue with number/code input.
- After language selection, all wizard explanatory copy uses the selected language family consistently for `ko`, `en`, `ja`, and `zh`.
- The first substantive setup step after language selection uses repo-state-first defaults: existing code keeps detected stack values, empty repos keep app stack unset.
- `b` and `back` navigation still work after language selection, including returning from later steps to the language step when appropriate.
- Plain line prompts remain available when raw-key interactive selection is unavailable.
- ASCII/plain output removes fragile emoji, ANSI-dependent styling, raw-key-only interaction, and color-only meaning while keeping labels, defaults, recommended choices, progress, and next steps readable.
- Non-interactive and `--yes` flows keep resolving the same profile defaults and do not require wizard input.

## Plain Output Contract

- Plain output must use line prompts and numeric/code choices.
- Plain output must retain the same information architecture as styled output: progress, current default, recommended choice, repo intelligence, Codex access preview, Git guidance, and ready handoff.
- Plain output must use text markers such as `[default]`, `[recommended]`, `[current]`, and `[next]` instead of color or emoji-only state.
- Plain output must avoid country flags, box-drawing layouts, alternate-screen behavior, and multi-column terminal layouts.
- Implement capability detection conservatively. Output should fall back to plain mode when raw-key selection, ANSI styling, emoji rendering, or UTF-8 terminal assumptions are not reliable.

## Language Surface Contract

- Language labels should be stable text-first labels such as `[ko] Korean`, `[en] English`, `[ja] Japanese`, and `[zh] Simplified Chinese`.
- `zh` maps to Simplified Chinese for generated docs and wizard copy, matching the existing `docs/getting-started.zh.md` surface.
- The default language marker must be visible before any localized explanatory copy is shown.
- Language selection must remain overridable by number and by language code in line mode.

## Implementation Notes

- Prefer small helper functions for wizard text, visual markers, and language-specific copy instead of scattering inline strings through `runInitWizard`.
- Keep terminal capability detection conservative. If capability is unknown, choose readable plain output.
- Treat emoji as optional decoration. Do not use country flags; prefer short language codes such as `[ko] Korean`, `[en] English`, `[ja] Japanese`, and `[zh] Simplified Chinese`.
- Keep wizard state transitions explicit and covered by tests, especially the language-first step order and conditional Git provider steps.
- Ensure docs generated by `renderNambaCLIGettingStartedBootstrapSection` and help from `initUsageText` describe the new first-run flow consistently.
