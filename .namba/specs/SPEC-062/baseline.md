# SPEC-062 Baseline

## Current State

Observed before implementation on branch `spec/SPEC-062-harness-quality-1-0`:

- `scripts/quality.sh` already includes Python unittest discovery, gofmt, `go vet`, `go test ./...`, harness eval regression, race tests, staticcheck, govulncheck, coverage report, and a 73.0 percent aggregate coverage threshold.
- `.github/workflows/ci.yml` already splits similar checks across baseline, analysis, vulnerability, race, and coverage jobs.
- `namba eval --suite harness --format json --baseline internal/namba/testdata/evals/harness/baseline.json --fail-on-regression` currently passes 26 of 26 scenarios with 0 baseline regressions.
- Current eval metrics include `route_selection`, `delivery_mode`, `artifact_targets`, `required_evidence`, `required_reviews`, `clarification`, `spec_required_fields`, and `execution_readiness`.
- `namba report --format json` emits `schema_version: namba-report/v1`.
- `namba report --format json` reports SPEC-062 as missing `contract.md`, `baseline.md`, and `eval-plan.md` until this evidence pack is added.
- README and workflow guides are generated by `namba sync`; the root README explicitly warns to edit the renderer or docs source rather than generated output only.
- `.namba/logs/queue/state.json` is currently runtime state without a `schema_version`; SPEC-062 treats it as parser compatibility input while `queue-runner-evidence/v1` remains the versioned queue evidence contract.

## Known Gaps

- JSON Schema contracts are not yet present for every evidence and report surface.
- Compatibility fixture tests do not yet cover historic evidence across run, queue, diagnostics, eval, baseline, and report JSON.
- The eval scorecard does not yet expose the complete 1.0 metric vocabulary.
- The eval scorecard needs an explicit compatibility layer so existing `namba-eval-results/v1` metric names can remain stable while 1.0 metric names are emitted in a scorecard contract.
- CI does not yet upload eval scorecard JSON, eval Markdown summary, report JSON, and schema validation artifacts as a combined evidence pack.
- Local and CI quality gate parity is implied by similar commands but not proven by a single canonical script invocation or checked mapping.
- `internal/namba` remains the main package for many unrelated boundaries.

## Baseline Comparison Policy

Implementation must compare against the checked-in baseline and fail on:

- metric pass count regression
- required coverage bucket disappearance
- scenario disappearance
- schema version incompatibility
- invalid report JSON
- invalid evidence fixture

Intentional baseline updates must be reviewed with fixture diffs and rationale.
